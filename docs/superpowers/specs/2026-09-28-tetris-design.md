# Тетрис на Python + pygame — дизайн

Дата: 2026-09-28

## Цель и контекст

Учебный проект: классический Тетрис на Python + pygame (окно на компьютере).
Автор — новичок в Python. Цель — не только рабочая игра, но и понимание,
как устроена программа и как делить её на части.

Следствия для кода:
- простой код с подробными комментариями на русском;
- классы используются умеренно (без наследования, декораторов и т.п.);
- логика отделена от графики и покрыта тестами pytest (знакомство с тестированием, TDD).

**Критерии готовности:**
1. Игра запускается командой `python main.py` из активированного `.venv`.
2. В неё можно играть от начала до game over и начать заново.
3. Все тесты (`pytest`) проходят.

## Объём первой версии

Входит: 7 фигур, сдвиг, вращение, мягкий сброс, жёсткий сброс, очистка линий,
счёт, уровни с ускорением, game over и рестарт.

Не входит (возможные будущие улучшения): превью следующей фигуры, «призрак»,
пауза, рекорды, Hold, вращение SRS, генератор 7-bag, звук.

## Структура проекта

```
tetris/

  game.py          — правила: падение, счёт, уровни, game over
  renderer.py      — отрисовка на pygame (только рисует)
  tests/
    test_pieces.py
    test_board.py
    test_game.py
  requirements.txt — pygame-ce, pytest
  README.md        — установка, запуск, тесты
  .gitignore
```

Поток данных идёт в одну сторону: **клавиши → `Game` → `renderer`**.
`pieces`, `board`, `game` не импортируют pygame.

## Раздел 1: фигуры и поле

### Поле (`board.py`)

- Константы `WIDTH = 10`, `HEIGHT = 20`.
- Класс `Board`, атрибут `grid`: список из 20 строк, в каждой 10 клеток.
  Пустая клетка — `None`, занятая — буква фигуры (`"T"`, `"I"`, …).
  Строка 0 — верхняя.
- `is_valid_position(piece) -> bool` — `True`, если каждая занятая клетка фигуры
  находится внутри поля (0 ≤ столбец < 10, строка < 20) и не пересекается
  с занятой клеткой поля. Клетки выше поля (строка < 0) считаются допустимыми,
  если они в пределах по ширине.
- `lock_piece(piece)` — записывает букву фигуры в клетки поля, где она находится.
- `clear_full_lines() -> int` — удаляет полностью заполненные строки, сверху
  добавляет столько же пустых и возвращает число удалённых строк.

### Фигуры (`pieces.py`)

- `SHAPES`: словарь «буква → форма», форма — список строк, где `"X"` — блок, `"."` — пусто:

  ```
  I: "....", "XXXX", "....", "...."
  O: "XX", "XX"
  T: ".X.", "XXX", "..."
  S: ".XX", "XX.", "..."
  Z: "XX.", ".XX", "..."
  J: "X..", "XXX", "..."
  L: "..X", "XXX", "..."
  ```

- `rotate_shape(shape) -> shape` — поворот квадратной формы на 90° по часовой стрелке.
  Четыре поворота подряд возвращают исходную форму.
- Класс `Piece`: атрибуты `letter`, `shape`, `row`, `col` (позиция левого верхнего угла формы).
  - `cells()` — список координат `(row, col)` занятых клеток на поле;
  - `moved(d_row, d_col) -> Piece` — копия, сдвинутая на смещение;
  - `rotated() -> Piece` — копия с повёрнутой формой.

  Методы возвращают **новые** объекты, так что «попробовать ход» можно без
  риска испортить текущую фигуру.
- `random_piece() -> Piece` — случайная буква (`random.choice`), позиция появления:
  `row = 0`, `col = (WIDTH - ширина формы) // 2`.

### Вращение

Пробуем повёрнутую фигуру на месте. Если позиция недопустима, пробуем её же
со сдвигом на 1 влево, затем на 1 вправо. Если все три варианта недопустимы,
поворот отменяется. Это упрощение, а не система SRS.

## Раздел 2: правила (`game.py`)

Класс `Game`. Атрибуты: `board`, `current` (текущая фигура), `score`, `level`,
`lines`, `game_over`, `fall_timer` (накопленные мс).

### Команды игрока

Во время `game_over` все команды, кроме `restart()`, ничего не делают.

| Метод | Действие |
|---|---|
| `move_left()` / `move_right()` | сдвиг на 1 клетку, если позиция допустима |
| `rotate()` | поворот с простым сдвигом от стенки (см. выше) |
| `soft_drop()` | если можно — вниз на 1 и +1 очко; если нельзя — фиксация |
| `hard_drop()` | вниз до упора, +2 очка за каждую пройденную клетку, затем фиксация |
| `restart()` | новое пустое поле, счёт 0, уровень 1, линии 0, новая фигура |

### Падение со временем

`update(dt_ms)` прибавляет `dt_ms` к `fall_timer`. Пока `fall_timer ≥ fall_interval()`,
вычитает интервал и опускает фигуру на 1 клетку (без очков). Если опустить нельзя —
фиксация.

`fall_interval() = max(100, 800 - (level - 1) * 70)` мс.

### Фиксация (внутренний метод `_lock_current`)

1. `board.lock_piece(current)`.
2. `cleared = board.clear_full_lines()`.
3. Начислить очки: `LINE_SCORES[cleared] * level`, где
   `LINE_SCORES = {0: 0, 1: 100, 2: 300, 3: 500, 4: 800}`.
4. `lines += cleared`; `level = 1 + lines // 10`.
5. Новая текущая фигура `random_piece()`, `fall_timer = 0`.
   Если её позиция недопустима — `game_over = True`.

Для тестов `Game` принимает необязательный параметр — функцию, выдающую
следующую фигуру (по умолчанию `random_piece`). Так тесты получают
предсказуемые фигуры.

## Раздел 3: отрисовка, управление, главный цикл

### Окно

Клетка 30×30 px. Поле 300×600 px слева, панель 200 px справа. Окно 500×600.
Заголовок окна — «Тетрис».

### Отрисовка (`renderer.py`)

`draw(screen, game)` только читает состояние:
- тёмный фон, сетка поля тонкими линиями;
- занятые клетки поля и текущая фигура, цвет по букве:
  I голубой, O жёлтый, T фиолетовый, S зелёный, Z красный, J синий, L оранжевый;
- панель: «Счёт», «Уровень», «Линии» с значениями;
- при `game_over`: полупрозрачное затемнение поля, надпись «Игра окончена»,
  ниже «R — заново».

Шрифт — `pygame.font.Font(None, размер)` (встроенный). Кириллицу встроенный шрифт
может не отобразить; в этом случае используем `pygame.font.SysFont` с системным
шрифтом, поддерживающим кириллицу (например, `"arial"`). Проверяется при запуске.

### Управление (`main.py`)

| Клавиша | Действие |
|---|---|
| ← / → | `move_left` / `move_right` |
| ↑ | `rotate` |
| ↓ | `soft_drop` |
| Пробел | `hard_drop` |
| R | `restart` (только при game over) |
| Esc, закрытие окна | выход |

Автоповтор при удержании: `pygame.key.set_repeat(170, 50)`.

### Главный цикл (`main.py`)

1. `pygame.init()`, окно, `clock = pygame.time.Clock()`, `game = Game()`.
2. Пока игра запущена:
   - `dt = clock.tick(60)`;
   - обработать события (клавиши → методы `Game`);
   - `game.update(dt)`, если не game over;
   - `draw(screen, game)`, `pygame.display.flip()`.
3. `pygame.quit()`.

## Раздел 4: тесты, окружение, ошибки

### Окружение

- Python 3.14 (есть в системе), виртуальное окружение `.venv`.
- `requirements.txt`: `pygame-ce`, `pytest`.
- Первый шаг реализации — проверить, что `pygame-ce` ставится на Python 3.14.
  Если нет — остановиться и обсудить варианты (другая версия Python через
  `uv`/`pyenv` или иное).
- `README.md`: создание окружения, установка, запуск игры и тестов, управление.

### Тесты (pytest, только логика)

- `test_pieces.py`: поворот формы T на 90°; 4 поворота = исходная форма;
  `cells()` учитывает позицию; `moved`/`rotated` не меняют исходную фигуру.
- `test_board.py`: фигура у левой/правой стенки и у дна; пересечение с занятой
  клеткой; клетки выше поля допустимы; `lock_piece` записывает буквы;
  очистка 1 линии и 4 линий, верхние строки сдвигаются вниз, возвращается число.
- `test_game.py`: сдвиг упирается в стенку; поворот у стенки со сдвигом;
  `hard_drop` даёт 2 очка за клетку и фиксирует; очки за линии × уровень;
  уровень 2 после 10 линий; `update(dt)` опускает фигуру только при накоплении
  интервала; game over при занятом месте появления; команды игнорируются при
  game over; `restart` сбрасывает состояние.

Реализация логики — через TDD: сначала падающий тест, затем код.
Отрисовку проверяем вручную запуском игры.

### Ошибки

Отдельной обработки ошибок почти нет: недопустимые ходы просто не выполняются,
во время game over команды движения игнорируются.
